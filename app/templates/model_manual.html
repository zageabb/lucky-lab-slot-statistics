CORE PROBABILITY

reels: cyclic strips

Exactly five arrays are required. The server selects one stop uniformly from each reel. That stop is the top visible symbol; the next two strip positions are the middle and bottom, wrapping around the end.

"reels": [
  ["clover", "harp", "clover", "emerald"],
  ["clover", "horseshoe", "harp", "rainbow"],
  ["harp", "clover", "crown", "emerald"],
  ["clover", "rainbow", "harp", "gold_pot"],
  ["horseshoe", "clover", "emerald", "crown"]
]
Frequency: two clovers in an eight-stop strip give clover a 2/8 stop frequency on that reel.
Order matters: rearranging symbols changes visible neighbours even if counts stay equal.
Exact combinations: reel 1 length × reel 2 length × … × reel 5 length.

WIN PATHS

paylines: paths through rows

Each line has five row indexes: 0 top, 1 middle and 2 bottom.

[0,0,0,0,0]Top
[1,1,1,1,1]Middle
[2,2,2,2,2]Bottom
[0,1,2,1,0]V shape
[2,1,0,1,2]Inverted V

Lines pay only 3–5 identical consecutive symbols beginning on reel 1. A break ends the count. For example, clover–clover–harp–clover–clover has only two consecutive clovers and does not pay.

RETURN SIZE

paytable: multipliers

"paytable": {
  "clover": {"3": 15, "4": 38, "5": 112},
  "gold_pot": {"3": 56, "4": 225, "5": 825}
}

Use JSON keys "3", "4" and "5". They are converted to match counts during validation.

line stake=total stake ÷ number of linesline payout=line stake × multiplier

At a 5.00 total stake with five lines, each line stake is 1.00. Three clovers at 15× return 15.00 credits. Raising frequent 3-match awards usually affects RTP broadly; concentrating value in rare 5-match awards generally increases volatility.

ACCOUNTING

allowed_stakes: integer units

"allowed_stakes": [100, 200, 500]

These display as 1.00, 2.00 and 5.00 virtual credits. Each must be positive and divide exactly by the number of paylines. Stake scales payout size but never changes stop probabilities.

IDENTITY

symbols: IDs and descriptions

"symbols": {
  "clover": "Four-leaf clover",
  "harp": "Celtic-inspired harp"
}

Every ID appearing on a reel must exist here. For its image to render, the ID must match an SVG filename in app/static/symbols/. Descriptions provide accessible alternative text.

RECIPES

Common changes

Make a symbol more frequent

Add another occurrence to one or more strips. A five-symbol line requires the symbol to be available on every reel. Publish and inspect the new exact statistics.

Raise or lower RTP

Change visible symbol counts or paytable multipliers. Publish a new version; never rename a model as a target without verifying the calculated result.

Increase volatility at similar RTP

Reduce frequent 3-match awards and increase rarer 4- or 5-match awards. Iterate until RTPs are similar, then compare variance, drawdown, streaks and risk of ruin.

Add a payline

Add a five-row path containing only 0–2. Update every allowed stake so it divides by the new line count. Recalculate because another line can change hit rate and RTP.

Add a symbol

Add its ID and description, paytable entry, reel occurrences, and a same-named SVG asset. A reel symbol without a paytable award simply cannot pay.

TROUBLESHOOTING

Common validation errors

five reels / three rowsVersion 1 fixes the board at 5 × 3.
unknown symbolA reel ID is absent from symbols.
valid row indexesA line is not five entries or contains a row outside 0–2.
stakes divide exactlyA stake cannot divide evenly across all lines.
definition hash existsAn identical definition is already published; make a real change.

Change one primary factor, publish, and compare using identical simulation settings. That makes cause and effect easier to teach.
